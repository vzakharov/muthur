the cloud environment's variables after its exec, so its /proc environ
carries none of them while the processes it spawns do. The telemetry
hook read that environ, judged the export off, printed the "capture is
off" notice and started no receiver on 127.0.0.1:4318, though the
operator had every variable set.

Where the nearest claude ancestor's environ names no
CLAUDE_CODE_ENABLE_TELEMETRY and the hook's own environment has it at
1, the hook now treats /proc as stale and takes its existing fallback:
start the receiver on that flag alone.

The OTEL_* variables that decide where events go stay invisible to
hooks, so such a start is now checked against what arrives: the
session's first event settles it, and a main-thread response that
finished more than 10 s after the start with still no event raises the
"capture is off" notice once, as PostToolUse context.
