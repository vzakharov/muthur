The Markdown wrap was the only format-on-edit rule the loop shipped,
and its hook and vet check had prettier and `*.md` written into them,
so an adopter wanting the same for code copied both and hard-coded its
own formatter and directories.

`scripts/format.py` is now the one mechanism: `hook` mode, wired as a
PostToolUse hook on Edit/Write/MultiEdit, formats the file just
edited; `check` mode, run by vet, checks every tracked file. Both read
`.claude/format.json`, a list of entries naming file globs, a format
command and a check command, so a formatter is an entry rather than a
script. The hook covers exactly what the check does: files inside the
project that git does not ignore. A formatter failure or a malformed
list is reported, never skipped.

Muthur's list carries one entry, the Markdown wrap, which replaces
`format-md.sh` and `check-markdown-wrap.sh`.

Adopters: your `.claude/settings.json` still wires
`.claude/hooks/format-md.sh`; replace that entry with
`scripts/format.py hook`, take `.claude/format.json`, and move any
local format hook of your own into an entry there. No operator
approval needed.
