```
fix: #172 hand a new-session sync's lock to the session that syncs (pr #173)
```

```
A new-session sync is claimed by the session that offers it, before it
spawns the one that syncs, so nobody takes the lock in between. The
claim's `Session:` trailer therefore named the offering session for the
whole sync, and every "who is syncing?" answer pointed at a session
doing unrelated work.

`scripts/muthur-sync.sh handover <session-id|url>`, run by the offering
session right after `create_session`, rewrites the lock with the claim's
tree, parent, dates and `Claimed-By:`, sets `Session:` to the spawned
session and keeps the claimer as `Spawned-By:`, which the lock's
description now prints. Only the current holder may hand over, a repeat
is a no-op, and the push is leased on the commit it read, so a takeover
landing in between wins and is reported with exit 3.

The nudge's offer rules and /update-muthur § "Offered at session start"
gain the step; claiming before spawning stays, since that is what
closes the race.

Fixes #172

```
