```
When `/from-branch` cannot resolve its target branch or PR, the single
most common cause is that the session is running against the wrong
repository — it is chosen per session from a dropdown that keeps the
previous selection, and with many repos in the list it is easily missed.
The old "stop and report" left that cause unranked, so a report led with
typo and never-pushed theories that send the operator digging in the
right repo for the wrong reason.

Step 1 now opens the failure report with the wrong-repo question — name
the repo the session is attached to and ask whether it is the intended
one — ahead of the typo / never-pushed / already-merged theories, which
only matter once the repo is confirmed. The reframing behind the
reordering: a missing branch is weak evidence the branch is wrong and
strong evidence the repo is.

`/handle` inherits this, its branch resolution delegating to
`/from-branch` Step 1, so the rule keeps a single home.
```
