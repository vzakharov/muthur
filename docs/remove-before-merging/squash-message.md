fix: cold-cache guard passes when a fresh session can't win (pr #146)
```

```
The cold-cache guard stops the first prompt after the cache expires so
the operator can weigh carrying on against a fresh session. When the
fresh session costs at least the re-cache up front and carries no
smaller context after, it never comes out ahead: the stop offers no
choice and only costs a round trip. An adopter session was stopped at
"carry on ~$0.33" against "new session ~$1.19, ~132k per request
instead of ~94k".

Such a prompt now passes, beside the COLD_CACHE_MIN_USD pass. A fresh
session that costs more up front but carries less context is still
offered, since it can win over a long enough tail.
